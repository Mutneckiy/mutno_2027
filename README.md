# Мутно · 2027

Небольшое приложение на FastAPI: пользователь указывает имя, дату рождения,
отвечает на пять вопросов и формулирует желание на 2027 год. Сервис возвращает
символическое послание и персональный векторный SVG-талисман для скачивания.
Приложение предназначено для развлечения и вдохновения, а не достоверного
предсказания будущего.

## Как работает приложение

Послание создаётся локальной LLM, если включено `LLM_ENABLED=true`.
Модель получает имя, дату рождения, желание, все пять ответов в читаемом виде
и рассчитанную символическую основу. При отключённой или недоступной модели,
занятом слоте, таймауте или некорректном ответе используется персональный шаблон.
Текст LLM может различаться при повторном запросе; SVG для одной анкеты стабилен.

Во время ожидания показываются «Обращаемся к оракулу…» и анимированный шар.
Результат содержит послание, символическую основу и скачиваемый талисман.

### Визуальный стиль

Тёмный звёздный фон, золото, глубокие бирюзовые и охристые оттенки создают
стиль старинного небесного атласа. Главный экран использует предоставленное
изображение `static/celestial-atlas.jpg` как декоративную иллюстрацию,
а не источник календарных расчётов. Тема — `static/celestial.css` поверх
базового `static/style.css`. Предыдущая светлая тема больше не подключается.

Талисманы возвращены к круглому орнаменту: золотые линии, звёзды и центральный
символ на тёмном фоне, оттенок которого зависит от выбранной стихии.
SVG имеет квадратное поле 512×512 с прозрачными углами и круглым медальоном.
Все персональные параметры сохранены. Шар ожидания использует золотую и
бирюзовую палитру; при `prefers-reduced-motion` анимация отключена.
Интерфейс адаптируется к телефону.

### Персональные талисманы

Это процедурная векторная графика (`talisman.py`), а не картинки нейросети.
Каждая анкета формирует собственную композицию вокруг одного из четырёх
базовых символов. Дополнительная модель изображений не требуется.

| Данные | Что меняется в рисунке |
| --- | --- |
| Вся анкета, включая имя, дату и желание | Центральный символ, поворот орнамента, расположение семи звёзд |
| Число пути по дате рождения | Количество лепестков: число пути + 3 |
| Западный знак и китайское животное | Две метки на внешних кольцах |
| Китайская стихия | Длина внешних лучей |
| Число имени | Количество точек под центральным символом |
| Личный год | Число рядом с 2027 |
| Ответ о стихии | Палитра |
| Ответ об источнике сил | Количество колец |
| Ответ о переменах | Ширина лепестков |
| Ответ о разрешении себе | Количество лучей |

Рисунок звёзд вымышленный и не изображает реальное созвездие.
Одинаковая анкета в одной версии генератора даёт одинаковый SVG; абсолютная
уникальность между всеми пользователями не гарантируется. Прямое скачивание
через API совпадает с изображением в результате. Имя, дата и желание не
встраиваются в SVG открытым текстом; сам талисман отражает символические числа
и знаки, поэтому не является способом анонимизации анкеты.

Приложение обрабатывает анкету в памяти и не сохраняет её в базе или логах.
В режиме LLM данные также передаются настроенному серверу модели;
его журналы и настройки хранения нужно учитывать отдельно.
Встроенная телеметрия FastAPI отключена.

## Быстрый запуск

Требуется Python 3.11+; CI проверяет Python 3.13 (версия Debian 13).

```bash
git clone https://github.com/Mutneckiy/mutno_2027.git
cd mutno_2027
python -m venv .venv
```

Активация в Linux/macOS:

```bash
source .venv/bin/activate
```

Активация в Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

```bash
python -m pip install -r requirements-dev.txt
```

Необязательно: скопировать `.env.example` в `.env` и изменить настройки.
В PowerShell: `Copy-Item .env.example .env`; в Linux: `cp .env.example .env`.

Обычный запуск без автоматической перезагрузки:

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8017 --no-access-log
```

Открыть http://127.0.0.1:8017/ и http://127.0.0.1:8017/docs.
Для разработки можно добавить `--reload`. Команды выполняются из корня проекта.

## Настройки

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| APP_TITLE | Мутно · 2027 | Название в OpenAPI |
| APP_VERSION | 0.1.0 | Версия в `/version` и OpenAPI |
| LOG_LEVEL | INFO | Уровень логирования: INFO, WARNING, DEBUG |
| LLM_ENABLED | false | Включить генерацию текста моделью |
| LLM_BASE_URL | http://127.0.0.1:18081/v1 | OpenAI-совместимый сервер через обратный SSH-туннель |
| LLM_MODEL | local | Идентификатор модели |
| LLM_API_KEY | пусто | Необязательный ключ сервера модели |

`.env` автоматически читается из папки проекта. Переменные процесса имеют
приоритет. Настоящий `.env` исключён из Git; в репозитории только `.env.example`.
Для применения настроек нужно перезапустить приложение.

## API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/` | Сайт с анкетой |
| GET | `/health` | Проверка работы, `status=ok` |
| GET | `/version` | Версия приложения |
| GET | `/api/questions` | Пять вопросов с вариантами |
| GET | `/api/talismans` | Каталог символов |
| POST | `/api/predictions` | Прогноз и SVG по параметрам анкеты |
| POST | `/api/talisman.svg` | Скачать SVG по параметрам анкеты |
| GET | `/docs` | Интерактивная документация API |

Пример тела POST (варианты ответов нумеруются от 0 до 3):

```json
{
  "full_name": "Андрей",
  "birth_date": "1987-10-06",
  "answers": {"direction": 0, "change": 1, "resource": 2, "element": 3, "step": 0},
  "wish": "Создать свой проект"
}
```

Неверные или пропущенные ответы, пустое имя, желание короче 3 символов и дата
рождения в будущем возвращают HTTP 422. Поля вне схемы запрещены.
SVG формируется из фиксированных геометрических элементов, а не пользовательской
разметки. В браузере пользовательские строки вставляются через `textContent`.

## Тесты и CI

```bash
python -m pytest -v
```

Проверяются health, версия из окружения, главная страница, статические файлы,
каталог вопросов и символов, персонализация, повторяемость, влияние ответов,
ошибочные параметры, SVG-скачивание и отсутствие анкетных данных в логах.

GitHub Actions (`.github/workflows/ci.yml`) запускается на каждый push и pull request.
После успешных тестов создаётся artifact `mutno-2027` с приложением и инструкциями.
Workflow проверяет и упаковывает приложение, но не разворачивает его на VPS.

## Debian 13: установка рядом с OpenClaw

Сначала проверить существующие слушающие порты и веб-серверы:

```bash
ss -lntup
systemctl status nginx caddy apache2 --no-pager
```

Если порты 80/443 уже заняты OpenClaw или другим прокси, необходимо добавить домен
в существующий прокси. Не запускать второй веб-сервер на тех же портах.
Ниже сценарий **для свободных портов 80, 443 и 8017**. Он не меняет конфигурацию
OpenClaw, firewall, SSH или VPN. Команды установки выполняются от root.

```bash
apt update
apt install -y git python3 python3-venv nginx certbot python3-certbot-nginx
adduser --system --group --no-create-home mutno
git clone https://github.com/Mutneckiy/mutno_2027.git /opt/mutno_2027
cd /opt/mutno_2027
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -v
cp .env.example .env
chown root:mutno .env
chmod 640 .env
cp deploy/mutno.service /etc/systemd/system/mutno.service
systemctl daemon-reload
systemctl enable --now mutno
curl --fail http://127.0.0.1:8017/health
```

Процесс работает от отдельного системного пользователя и слушает только loopback.
Папка проекта остаётся под управлением root; приложению запись на диск не требуется.

Настройка HTTP, если Nginx выбран в качестве внешнего прокси:

```bash
cp deploy/mutno.nginx.conf /etc/nginx/sites-available/mutno
ln -s /etc/nginx/sites-available/mutno /etc/nginx/sites-enabled/mutno
nginx -t && systemctl reload nginx
```

В DNS SpaceWeb создать A-запись для основного домена (пустой поддомен) и `www`,
значение `213.183.51.225`. Домен должен использовать DNS-серверы SpaceWeb.
Если есть старые A/AAAA-записи, ведущие на другие серверы, их нужно исправить.
AAAA пока не добавлять: конфигурация выше сначала проверяется по IPv4.

Проверка DNS и HTTP:

```bash
getent ahostsv4 mutno.online
getent ahostsv4 www.mutno.online
curl --fail http://mutno.online/health
```

Порты TCP 80/443 должны быть доступны извне; если есть firewall в панели провайдера
или на VPS, разрешить их, сохранив доступ по SSH. После правильного DNS включить HTTPS:

```bash
certbot --nginx -d mutno.online -d www.mutno.online --redirect
certbot renew --dry-run
curl --fail https://mutno.online/health
curl --fail https://mutno.online/version
```

Certbot задаст вопросы о почте и условиях выпуска сертификата. Если `www` ещё
не настроен, сначала исправить его DNS либо выпускать только для `mutno.online`.
До HTTPS пользоваться только вымышленными тестовыми данными.

## Логи и диагностика

Локально сообщения идут в терминал. На VPS:

```bash
systemctl status mutno --no-pager
journalctl -u mutno -n 100 --no-pager
journalctl -u mutno -f
nginx -t
tail -n 50 /var/log/nginx/mutno-error.log
```

Приложение логирует запуск/остановку, HTTP-метод, путь, код ответа и длительность.
Тела анкет и параметры URL не логируются. Поставляемая команда отключает access-log
Uvicorn; конфигурация Nginx отключает access-log именно для этого сайта.

| Проблема | Что проверить |
| --- | --- |
| 502 от Nginx | `systemctl status mutno`, затем `curl http://127.0.0.1:8017/health` |
| Address already in use | `ss -lntup`; не останавливать OpenClaw, согласовать другой порт и прокси |
| Домен ведёт не туда | A/AAAA, DNS-серверы домена, DNS-кеш |
| Ошибка сертификата | A-записи обоих имён, доступность TCP 80 извне |
| HTTP 422 | Все пять ответов 0–3, дата не в будущем, ограничения длины |
| Вопросы не загрузились | `/health`, `/api/questions`, логи и соединение |
| ModuleNotFoundError | Активирована ли `.venv`, установлены ли зависимости |

Обновление после загрузки новых коммитов в GitHub:

```bash
cd /opt/mutno_2027
git pull --ff-only
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -v && systemctl restart mutno
```

## Домашняя модель и VPS

Настройка модели и туннеля описана в [deploy/LLM.md](deploy/LLM.md).
Рабочая цепочка: браузер → HTTPS/Nginx → FastAPI `127.0.0.1:8017` →
обратный SSH-туннель `127.0.0.1:18081` на VPS → llama.cpp `127.0.0.1:8081`
на Windows. WireGuard для этой цепочки не требуется. Обе стороны туннеля
должны использовать loopback, а не адрес отключённого VPN.

Модель и SSH-туннель должны запускаться Планировщиком Windows при загрузке
компьютера, независимо от входа пользователя. Проверяйте обе задачи после
перезагрузки без интерактивного входа. На VPS доступность модели проверяется
командой `curl --fail http://127.0.0.1:18081/health`.

`/health` самого приложения сообщает настроенный режим, но не проверяет модель.
Фактический режим конкретного послания возвращается в поле `mode` ответа
`/api/predictions`. Один запрос обслуживается моделью; при занятости остальные
получают шаблон. Таймаут HTTP-клиента модели — 45 секунд, соединения — 3 секунды,
ожидания в браузере — 100 секунд. Подробности и ограничения — в инструкции LLM.

## Оракул и символическая основа

Во время запроса показываются «Обращаемся к оракулу…» и анимированный CSS-шар.
Анимация отключается при системной настройке уменьшения движения; после ответа
или ошибки шар скрывается. SVG-талисман по-прежнему формируется приложением.

`symbolism.py` рассчитывает основу для LLM и шаблонного режима:
- западный солнечный знак по условным календарным границам (без натальной карты);
- китайское животное и стихию по лунному году рождения, включая даты до Нового года;
- числа пути и личного года, сведённые к 1–9;
- число всего введённого имени/ФИО по авторской схеме: русский алфавит с ё и латинский
  A–Z, циклические значения 1–9. Пробелы и прочие символы пропускаются. При отсутствии
  поддерживаемых букв число имени не вычисляется.

Это творческая развлекательная смесь традиций, а не научный прогноз.
Поле `symbolic_profile` содержит расчёты и описание метода. LLM получает эти
значения вместе с текстами всех пяти выбранных ответов и пожеланием. Инструкция
требует связать ответы с символами и конкретными шагами, не придумывать натальную
карту и не обещать события. Качество текста нужно также проверять на живой модели.

Китайский календарь: [lunar-python](https://github.com/6tail/lunar-python).
Граница 2027 года: [6 февраля](https://www.labour.gov.hk/eng/news/latest_holidays2027.htm).
Тесты покрывают обе стороны лунного Нового года, нижнюю границу 1900 года,
западные календарные границы, нормализацию имени и передачу основы в LLM.
