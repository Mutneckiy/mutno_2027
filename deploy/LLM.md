# Домашняя LLM через обратный SSH-туннель

Сайт обращается к OpenAI-совместимому llama-server через
`http://127.0.0.1:18081/v1`. Удалённый порт SSH привязан к loopback VPS.
Публично открывать порт модели не требуется.

## Запуск дома

Для независимости от WireGuard перезапустите llama-server с прежними параметрами
модели, но `--host 127.0.0.1 --port 8081`. Затем в отдельном PowerShell:

```powershell
ssh -N -T `
  -o ExitOnForwardFailure=yes `
  -o ServerAliveInterval=20 `
  -o ServerAliveCountMax=3 `
  -R 127.0.0.1:18081:127.0.0.1:8081 `
  root@213.183.51.225
```

Оба процесса должны оставаться запущенными, компьютер не должен спать.
Эта команда пока не обеспечивает автоперезапуск SSH. Для постоянной эксплуатации
следующий этап — отдельный SSH-пользователь с ограниченным пробросом порта,
ключ и задача Windows с автоматическим переподключением.

## Обновление VPS

Проверьте, что рабочая копия чистая (`git status --short`), затем:

```bash
cd /opt/mutno_2027
git pull --ff-only
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -v
```

Только после успешных тестов включите модель в существующем `.env`:

```ini
LLM_ENABLED=true
LLM_BASE_URL=http://127.0.0.1:18081/v1
LLM_MODEL=local
```

`LLM_API_KEY` необязателен и нужен, если llama-server запущен с ключом API.
Файл `.env` не включается в Git. Изменения читаются после перезапуска сервиса.

В `/etc/nginx/sites-available/mutno` поменяйте существующую строку
`proxy_read_timeout 30s;` на `proxy_read_timeout 90s;`.
Не заменяйте весь конфиг файлом из репозитория: Certbot уже добавил HTTPS.

```bash
nginx -t && systemctl reload nginx
systemctl restart mutno
curl --fail http://127.0.0.1:18081/health
curl --fail https://mutno.online/health
```

`/health` показывает настроенный режим (`llm`), а не доступность модели.
Фактический режим каждого результата находится в `mode` ответа
`POST /api/predictions`: `llm` или `template`.

Проверьте анкету при запущенной модели, затем закройте SSH и повторите запрос:
сайт должен вернуть шаблонный результат. После проверки восстановите туннель.

## Поведение

Модель получает имя, дату рождения, выбранные ответы, пожелание и параметры
талисмана. Данные передаются на домашний компьютер через SSH, не сохраняются
приложением и не записываются в его журнал. Отдельно учитывайте настройки
журналирования самого llama-server.

LLM возвращает только заголовок, вступление и три раздела в JSON по схеме.
SVG остаётся детерминированным: скачанный файл соответствует показанному.
Произвольная разметка модели не выполняется браузером.

Одновременно обрабатывается один запрос LLM на процесс приложения. При занятости,
ошибке соединения, тайм-ауте, незавершённом или неверном JSON выдаётся шаблон.
HTTP-клиент ограничивает подключение тремя секундами и ожидание данных 45 секундами;
ответ ограничен 64 КиБ. Автотесты используют подставные ответы и не требуют модели.

Чтобы выключить интеграцию, задайте `LLM_ENABLED=false` и перезапустите `mutno`.
